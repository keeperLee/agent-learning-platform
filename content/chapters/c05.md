# 感知—规划—行动—反思：Agent 主循环

第 1 章给出的三行伪代码是 Agent 的骨架。这一章我们把它拆开，逐段看工程上到底要写什么。

## 循环的四个阶段

:::diagram loop caption="图 5-1 · 主循环：四个阶段交替推进，反思决定是否继续"
:::

| 阶段 | 输入 | 输出 | 关键工程问题 |
| --- | --- | --- | --- |
| **感知 Perceive** | 用户消息、工具返回、环境变化 | 结构化的当前状态 | 什么该进上下文？噪声如何过滤？ |
| **规划 Plan** | 目标 + 状态 + 可用工具 | 下一步动作（或计划列表） | 决策是否可靠？能否被校验？ |
| **行动 Act** | 动作描述 | 工具调用结果 | 参数校验、超时、重试、幂等 |
| **反思 Reflect** | 动作 + 结果 | 继续 / 修正 / 终止 | 终止条件怎么定？无进展怎么识别？ |

:::callout key 一个常见的实现错误
很多实现只写了「规划 → 行动」两段，跳过了显式的**反思**。结果是：Agent 会一直调用工具，因为没有任何环节在判断"我是不是已经完成了"。**反思阶段的缺失，是死循环和无意义调用最主要的成因。**
:::

## 感知阶段：决定"看什么"

感知的本质是**上下文选择**。模型能看到的只有你喂给它的东西，所以这一阶段的目标是：**用最少的 token 承载最多的有效信息**。

一个实用的信息分层：

```python {3-9} title="感知阶段的上下文组装"
def build_context(state):
    return {
        "system": SYSTEM_RULES,                    # 固定：角色、边界、输出格式
        "goal": state.original_goal,               # 每轮重述，防止跑偏
        "progress": summarize(state.history),      # 压缩：已完成什么
        "evidence": state.retrieved[:5],           # 筛选：只放最相关的证据
        "last_result": state.last_tool_result,     # 最近一次结果（高优先级）
        "available_tools": TOOL_SCHEMAS,           # 工具描述
    }
```

:::callout tip 感知阶段的两个实用技巧
1. **工具结果要裁剪**。一个搜索工具可能返回 20KB 文本，直接塞进上下文会挤掉其他所有信息。做法：截断 + 提取关键字段 + 保留原文引用 ID 供后续按需回查。
2. **目标每轮重述**。把 `original_goal` 放在上下文的靠后位置（利用位置效应），能显著降低跑偏概率。
:::

## 规划阶段：产出可校验的动作

规划的输出必须是**机器可校验的结构**，而不是自由文本。这是可靠性的第一道闸门：

```json {1-7} title="规划输出的标准结构"
{
  "reasoning": "用户问的是上季度报销标准，我的记忆里没有确切数字，需要检索",
  "action": "tool_call",
  "tool": "search_knowledge_base",
  "args": { "query": "差旅报销标准 2026Q3", "top_k": 3 },
  "confidence": 0.86
}
```

有了 `action` 字段，运行时就能做分支处理：

```python {3-10} title="基于结构化动作的分支"
plan = llm_plan(context)
if plan.action == "tool_call":
    validate(plan)          # 参数 schema 校验
    execute(plan)
elif plan.action == "final_answer":
    return plan.content
elif plan.action == "ask_user":
    return ask(replan.content)    # 主动澄清，而不是瞎猜
else:
    raise InvalidPlan(plan)
```

:::callout info 为什么要有 `ask_user`
让 Agent 具备"承认信息不足并主动提问"的能力，比让它硬猜要可靠得多。很多失败的 Agent 系统，问题不在推理能力，而在**从不提问**。
:::

## 行动阶段：把不确定性关进笼子

行动阶段的原则是：**永远不信任模型给的参数**。

```python {4-14} title="工具执行的防御性写法"
def execute_tool(tool_name, args, ctx):
    tool = TOOLS.get(tool_name)
    if tool is None:
        return error(f"未知工具 {tool_name}，可用工具：{list(TOOLS)}")

    err = tool.schema.validate(args)           # 1. 参数校验
    if err:
        return error(f"参数错误：{err}。请修正后重试。")

    if not ctx.has_permission(tool, args):     # 2. 权限校验
        return error("当前用户无权执行该操作")

    try:                                       # 3. 超时 + 重试
        return call_with_retry(tool, args, timeout=tool.timeout, max_retry=tool.max_retry)
    except ToolTimeout:
        return error("工具执行超时，请考虑换用其他工具或缩小查询范围")
```

注意最后返回的是**给模型看的自然语言错误**，而不是异常栈。这一点非常重要：

:::callout warn 错误信息的两种写法
- ❌ `Traceback (most recent call last): ...` —— 模型看不懂，只会重复同样的错误。
- ✅ `参数错误：'start_date' 必须是 YYYY-MM-DD 格式，你提供的是 '2026/7/1'。请修正后重试。` —— 模型能立刻自我纠正。

**错误信息是给模型的"教学材料"，写得越具体，自我修复成功率越高。**
:::

## 反思阶段：一切可靠性的来源

反思是主循环里最容易被低估的阶段。它至少要回答四个问题：

| 问题 | 判断方式 | 不满足时怎么办 |
| --- | --- | --- |
| **目标达成了吗？** | 模型自评 + 确定性校验双保险 | 继续循环 |
| **有进展吗？** | 对比连续 N 步的状态指纹 | 无进展 → 换策略或终止 |
| **成本还够吗？** | 累计 token / 调用次数 / 耗时 | 超预算 → 降级或中止 |
| **出错了吗？** | 工具返回的错误标记 | 失败 N 次 → 换工具或转人工 |

### 无进展检测：一个廉价但极有效的手段

```python {5-12} title="无进展检测"
seen = set()
for step in range(MAX_STEPS):
    plan = llm_plan(context)
    fingerprint = hash((plan.action, json.dumps(plan.args, sort_keys=True)))
    if fingerprint in seen:
        repeat_count += 1
        if repeat_count >= 2:                     # 同一个动作重复 3 次
            context.append(system("你已重复执行相同动作且无新信息，请改变策略或终止。"))
    seen.add(fingerprint)
```

这段代码只有几行，但能拦掉线上相当比例的"无效循环"。**它的思路是：不判断模型对不对，只判断它有没有在做重复的事。**

### 终止条件的四道闸门

```python {2-5} title="终止条件"
def should_stop(state):
    return (
        state.goal_achieved                          # 1. 目标达成（模型自评 + 校验）
        or state.steps >= MAX_STEPS                   # 2. 步数上限
        or state.tokens >= MAX_TOKENS                 # 3. 成本上限
        or state.elapsed >= MAX_SECONDS               # 4. 时间上限
    )
```

:::callout danger 四个上限都必须有，缺一不可
- 只有步数上限 → 长文本工具调用可能一次就烧掉整个预算。
- 只有成本上限 → 便宜但没用的工具调用可以无限循环。
- 只有时间上限 → 高峰期会堆积大量超时任务。

**它们不是"为了保险起见"的兜底，而是循环能够安全存在的必要前提。**
:::

## 完整实现

把四个阶段拼起来，就是一个可运行的最小骨架：

```python {1-3,15-22} title="agent_loop.py"
class AgentState:
    def __init__(self, goal, tools):
        self.original_goal = goal
        self.history = []          # [(thought, action, observation)]
        self.steps = 0
        self.tokens = 0
        self.started_at = time.time()


def run_agent(goal, tools, budget=Budget(steps=12, tokens=60_000, seconds=90)):
    state = AgentState(goal, tools)
    while not should_stop(state, budget):                 # 反思：是否该停
        ctx = build_context(state)                        # 感知：组装上下文
        plan = llm_plan(ctx, tools.schemas())             # 规划：结构化决策
        state.tokens += plan.tokens_used

        if plan.action == "final_answer":                 # 终止：目标达成
            return Result(ok=True, content=plan.content, state=state)

        observation = execute_tool(plan.tool, plan.args, ctx)  # 行动
        state.history.append((plan.reasoning, plan, observation))
        state.steps += 1

        if is_stuck(state.history):                       # 反思：无进展
            state.history.append(system_hint("重复动作，请改变策略"))

    return Result(ok=False, content="任务未在预算内完成", state=state)
```

## 本章要点

- 主循环 = **感知 → 规划 → 行动 → 反思**，四段缺一不可。
- **感知**是上下文选择问题：目标重述、结果裁剪、证据筛选。
- **规划**必须产出可校验的结构化动作，并允许 `ask_user`。
- **行动**永不信任模型参数：schema 校验 + 权限校验 + 超时重试，错误以自然语言回灌。
- **反思**是可靠性的来源：目标达成、进展检测、预算检查、错误处理。
- **四道终止闸门**（目标/步数/成本/时间）是循环能安全存在的必要条件。
