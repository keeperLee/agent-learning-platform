# 术语表

这一章是查阅用的。Agent 领域最麻烦的不是概念难，而是**同一个概念有五六种叫法，不同叫法之间还有细微差别**。下表按主题归类，给出一句话定义和对应章节。

## 基础与角色

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **Agent（智能体）** | 能自主决定下一步并动手执行、且能根据结果调整的系统。判据：自主决策 + 工具行动 + 闭环反馈 | [第 1 章](#/chapter/c01) |
| **Workflow（工作流）** | 控制流由代码写死的编排。路径通过 LLM 与 Agent 拼装，但**判断权在人手里**。与 Agent 的界线是控制权归属 | [第 1 章](#/chapter/c01) |
| **LLM 应用** | 提示词模板 + 单次（或少数几次）模型调用，控制流完全由代码决定 | [第 2 章](#/chapter/c02) |
| **ReAct** | Reason + Act，推理与行动交替进行的范式。Agent 主循环的理论原型 | [第 6 章](#/chapter/c06) |
| **L1–L4 分级** | 按"决策权在谁手里"把 AI 系统分成规则程序 / 机器学习 / LLM 应用 / Agent 四级 | [第 2 章](#/chapter/c02) |
| **Human-in-the-loop（HITL）** | 关键节点插入人工确认或审批。生产系统的必备降级路径 | [第 15 章](#/chapter/c15) |
| **Agentic** | 形容词，指"具备 Agent 特性"。常被滥用，看到时建议追问：控制流在谁手里 | — |

## 推理与规划

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **CoT（Chain-of-Thought，思维链）** | 让模型在给答案前先输出推理过程，显著提升复杂任务表现 | [第 3 章](#/chapter/c03) |
| **Self-Consistency（自洽性）** | 采样多条推理路径，取多数一致的答案。用算力换准确率 | [第 6 章](#/chapter/c06) |
| **ToT（Tree of Thoughts，思维树）** | 把推理组织成树，每个节点展开多个候选并打分，可回溯 | [第 6 章](#/chapter/c06) |
| **Plan-and-Execute** | 先一次性产出完整计划，再按依赖顺序执行，失败时重规划 | [第 6 章](#/chapter/c06) |
| **Replanning（重规划）** | 执行中发现计划失效时，**增量**调整剩余计划。必须设上限 | [第 6 章](#/chapter/c06) |
| **Task Decomposition（任务分解）** | 把目标拆成可执行、可验证的子任务，并标注依赖 | [第 6 章](#/chapter/c06) |
| **Reflection（反思）** | 对已有结果做评估并据此调整下一步。Agent 可靠性的主要来源 | [第 5 章](#/chapter/c05) |
| **Self-Refine** | 自我critique → 自我修订的迭代循环 | [第 5 章](#/chapter/c05) |
| **Termination Condition（终止条件）** | 决定循环何时停止。至少要有目标达成 / 步数 / 成本 / 时间四道闸门 | [第 5 章](#/chapter/c05) |
| **No-Progress Detection（无进展检测）** | 通过动作指纹比对发现"在原地打转"，并强制换策略或终止 | [第 5 章](#/chapter/c05) |

## 记忆与上下文

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **Context Window（上下文窗口）** | 模型单次调用能看到的 token 上限。相当于 Agent 的工作内存（RAM） | [第 3 章](#/chapter/c03) |
| **Context Engineering（上下文工程）** | 决定"什么信息、在什么位置、以什么形式"进入上下文。Agent 开发的主要工作量所在 | [第 9 章](#/chapter/c09) |
| **Working Memory（工作记忆）** | 当前上下文窗口里的内容。快、贵、容量小 | [第 7 章](#/chapter/c07) |
| **Session Memory（会话记忆）** | 单次任务的结构化状态（目标、已完成、事实）。比原始对话省 token 且更抗漂移 | [第 7 章](#/chapter/c07) |
| **Long-term Memory（长期记忆）** | 跨会话持久化的记忆，通常落在向量库 / KV / 图数据库 | [第 7 章](#/chapter/c07) |
| **Lost in the Middle（中间遗忘）** | 实证现象：模型对上下文开头和结尾的利用率明显高于中间 | [第 3 章](#/chapter/c03) |
| **Rolling Summary（滚动摘要）** | 把早期对话压成摘要，保留最近若干轮原文。压缩时必须显式指定"保留什么、丢弃什么" | [第 9 章](#/chapter/c09) |
| **Lazy Loading（延迟加载 / 按需回查）** | 上下文里只放引用 ID，需要细节时再调工具取。把上下文问题转成工具问题 | [第 9 章](#/chapter/c09) |
| **Memory Decay（记忆衰减）** | 按时间给记忆降权，不同类型衰减速度不同 | [第 7 章](#/chapter/c07) |
| **Superseded（记忆失效标记）** | 新记忆与旧记忆冲突时的处理方式：标记而非删除，保留可追溯性 | [第 7 章](#/chapter/c07) |

## 工具与协议

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **Function Calling / Tool Calling** | 模型输出结构化的"调用意图"，由运行时执行。**模型本身不执行任何工具** | [第 8 章](#/chapter/c08) |
| **Tool Schema** | 用 JSON Schema 描述工具参数。既给模型看，也用于执行前校验 | [第 8 章](#/chapter/c08) |
| **Structured Output（结构化输出）** | 强制模型输出可解析的结构（JSON mode / schema 约束） | [第 3 章](#/chapter/c03) |
| **MCP（Model Context Protocol）** | 工具的标准化接入协议，把"工具提供方"和"使用方"解耦。解决接入效率，**不解决安全** | [第 8 章](#/chapter/c08) |
| **MCP Server / Client** | Server 提供 tools / resources / prompts；Client 是 Agent 运行时一侧 | [第 8 章](#/chapter/c08) |
| **Idempotency Key（幂等键）** | 保证同一请求重复执行只生效一次。所有写操作必备 | [第 8 章](#/chapter/c08) |
| **Exponential Backoff（指数退避）** | 重试间隔指数增长，避免加重限流。配合"缩小参数范围"更有效 | [第 8 章](#/chapter/c08) |
| **Tool Granularity（工具粒度）** | 一个工具应对应"一个业务语义完整的动作"。太细导致步骤爆炸，太粗等于没工具 | [第 8 章](#/chapter/c08) |

## 架构与编排

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **Orchestrator（编排者）** | 多 Agent 架构中负责拆解、派发、汇总的角色 | [第 11 章](#/chapter/c11) |
| **Supervisor 模式（主管制）** | 一个编排者 + N 个专家 Worker 的拓扑 | [第 11 章](#/chapter/c11) |
| **Blackboard（黑板）** | 多 Agent 共享一块结构化状态区，各自读写自己负责的部分 | [第 11 章](#/chapter/c11) |
| **Group Chat（群聊 / Debate）** | 多 Agent 在同一会话轮流发言。最容易失控，需硬性轮数上限 | [第 11 章](#/chapter/c11) |
| **Handoff（移交）** | 把控制权从一个 Agent 转给另一个（或转人工） | [第 11 章](#/chapter/c11) |
| **State Machine（状态机）** | 节点固定、模型只在节点内决策的编排方式。可预测、可审计 | [第 10 章](#/chapter/c10) |
| **Checkpoint（检查点）** | 持久化中间状态，用于断点续跑与人机协同 | [第 12 章](#/chapter/c12) |
| **Executor / Runtime（执行环境）** | 承担参数校验、权限、超时、重试、审计的一层。**Agent 从脚本走向系统的标志** | [第 10 章](#/chapter/c10) |
| **Loop Detection（环检测）** | 状态机层面识别 `A → B → A` 这类回退循环并强制中止 | [第 10 章](#/chapter/c10) |

## 检索与知识

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **RAG（Retrieval-Augmented Generation）** | 先检索证据再生成回答。效果上限由**检索质量**决定，而非生成模型 | [第 13 章](#/chapter/c13) |
| **Chunking（切分）** | 把长文档切成可检索的块。要点：拼入标题路径、保留重叠、表格整块 | [第 13 章](#/chapter/c13) |
| **Embedding（嵌入 / 向量化）** | 把文本映射为向量，用于相似度计算 | [第 13 章](#/chapter/c13) |
| **Bi-encoder / Cross-encoder** | 双塔（快、粗）vs 交叉编码器（慢、精）。前者召回、后者重排 | [第 13 章](#/chapter/c13) |
| **Rerank（重排）** | 用交叉编码器对召回结果精排。**RAG 优化中投入产出比最高的一步** | [第 13 章](#/chapter/c13) |
| **Hybrid Search（混合检索）** | 向量检索 + 关键词检索（BM25）融合，兼顾语义与精确匹配 | [第 13 章](#/chapter/c13) |
| **RRF（Reciprocal Rank Fusion，倒数排名融合）** | 融合多路检索结果的常用算法，不需要调权重 | [第 13 章](#/chapter/c13) |
| **Multi-hop Retrieval（多跳检索）** | 后一次检索依赖前一次结果。研究型 Agent 的核心能力 | [第 13 章](#/chapter/c13) |
| **Agentic RAG** | 把检索变成可反复调用、可换参数的工具，而非固定流程中的一步 | [第 13 章](#/chapter/c13) |
| **Recall@K / Precision@K** | 正确文档是否在 Top-K 中 / Top-K 中有多少相关。**必须单独测召回率** | [第 13 章](#/chapter/c13) |
| **Faithfulness（忠实度）** | 回答是否完全基于召回内容，不引入上下文之外的信息 | [第 13 章](#/chapter/c13) |

## 评估与运维

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **Trace（调用链）** | 一次运行的完整记录：每步决策、tokens、耗时、错误、prompt 版本 | [第 14 章](#/chapter/c14) |
| **Prompt Hash（提示词指纹）** | 提示词版本标识。没有它就无法归因"效果变化是不是改提示词导致的" | [第 14 章](#/chapter/c14) |
| **Eval Set（评估集）** | 有代表性的测试用例集合。需覆盖正常 / 边界 / 安全 / 回归四类 | [第 14 章](#/chapter/c14) |
| **Regression Case（回归用例）** | 每个线上 bug 修复后固化进评估集，防止复发。评估集最大的价值来源 | [第 14 章](#/chapter/c14) |
| **LLM-as-a-Judge** | 用模型做评估。已知偏差：位置偏差、长度偏差、自我偏好 | [第 14 章](#/chapter/c14) |
| **Shadow Mode（影子模式）** | 只出结果不给用户看，用于零风险收集真实数据 | [第 20 章](#/chapter/c20) |
| **Golden Set（黄金集）** | 人工精心标注、可信度最高的评估子集，用于校准自动评估 | [第 14 章](#/chapter/c14) |
| **Cost per Task（单任务成本）** | Agent 场景必须单独度量的指标。只看准确率会得出误导性结论 | [第 14 章](#/chapter/c14) |

## 安全与风险

| 术语 | 一句话定义 | 章节 |
| --- | --- | --- |
| **Prompt Injection（提示注入）** | 通过外部内容注入指令劫持 Agent。**根源是模型无法区分"指令"和"数据"** | [第 15 章](#/chapter/c15) |
| **Indirect Injection（间接注入）** | 注入载体是网页、文档、邮件等 Agent 会读取的外部内容 | [第 15 章](#/chapter/c15) |
| **Guardrail（护栏）** | 模型之外的确定性校验层。分输入 / 动作 / 输出 / 预算 / 审计五道 | [第 15 章](#/chapter/c15) |
| **Fail-closed（默认拒绝）** | 护栏失效时"什么都不做"，而不是"什么都允许"。安全设计的默认姿态 | [第 15 章](#/chapter/c15) |
| **Least Privilege（最小权限）** | 只授予完成任务所必需的最小权限。**最有效的单一安全措施** | [第 15 章](#/chapter/c15) |
| **PII（Personal Identifiable Information）** | 个人可识别信息。输出侧必须脱敏，检索侧必须按权限过滤 | [第 15 章](#/chapter/c15) |
| **Hallucination（幻觉）** | 生成流畅、格式正确但事实错误的内容。Agent 场景下会被后续步骤当事实使用 | [第 4 章](#/chapter/c04) |
| **Error Compounding（错误累积）** | 多步任务的失败率是**乘法**的：8 步 95% 成功率 = 66% 整体成功率 | [第 4 章](#/chapter/c04) |
| **Red Teaming（红队测试）** | 上线前主动攻击自己的系统，尝试注入、越权、诱导泄露 | [第 15 章](#/chapter/c15) |
| **Budget / Circuit Breaker（预算与熔断）** | 三层上限（单任务 / 单用户 / 全系统），是循环能安全存在的前提 | [第 15 章](#/chapter/c15) |

:::callout tip 三个最容易被混用的词
1. **Workflow vs Agent**：看控制流在谁手里，不看是否用了 LLM。
2. **MCP vs Function Calling**：前者是接入协议（解决重复适配），后者是调用机制。MCP 不解决安全。
3. **RAG vs Agentic RAG**：前者是固定流程（检索 → 生成），后者是把检索变成模型可自主调用的工具。

第 2 章那套"决策权归属"的分级方法，可以用来拆解几乎所有混用场景。
:::

## 本章要点

- 术语混乱的根源是**决策权归属不清**。遇到新名词先问：它接管了哪部分控制权？
- 最易混淆的三组：Workflow/Agent、MCP/Function Calling、RAG/Agentic RAG。
- 需要一个**快速索引**时，直接在本页用 `Ctrl/⌘ + K` 搜索术语名即可定位。
