# 案例四：深度研究 Agent

深度研究 Agent 要回答的是**开放性问题**：

> "2026 年企业级 AI Agent 的落地现状如何？"

没有标准答案，信息分散在几十上百个来源里，且质量参差不齐。这一章讲怎么在这种"完全开放"的场景里做出可信的产出。

## 研究循环

```text
目标
 ↓
① 拆解为若干研究子问题（发散）
 ↓
② 对每个子问题检索 → 阅读 → 抽取（收集证据）
 ↓
③ 交叉验证：多个来源是否相互印证？
 ↓
④ 识别信息缺口 → 回到 ② 补充检索（收敛）
 ↓
⑤ 组织成文：结论 + 论据 + 引用
```

:::callout key 关键差别：这个循环要"发散再收敛"
普通的检索问答是"找到就答"。研究 Agent 必须先**主动扩大信息面**（否则结论片面），再**逐步收敛到可信结论**（否则永远在搜集）。

控制手段：**前 N 轮只收集不结论，之后强制进入"缺口识别 + 收敛"阶段**。
:::

## 步骤一：拆解研究问题

好的研究会把大问题拆成**可检索、可验证**的子问题：

```text {1-9} title="研究计划示例"
主问题：2026 年企业级 AI Agent 落地现状

子问题：
1. 市场规模与增长率（需要量化数据、多来源交叉）
2. 主要采用场景分布（客服/编程/数据分析/内部工具）
3. 落地的主要障碍（技术、成本、组织）
4. 典型成功案例与失败教训
5. 与 2024 年相比的变化

每个子问题需标注：需要的证据类型、可接受的信息源等级、预期答案形态
```

:::callout tip 给每个子问题指定"证据标准"
```text
子问题 1（市场规模）：
  需要的证据：至少 2 个独立来源，需给出数字与口径
  可接受来源：行业报告、上市公司财报、官方统计
  不可接受：营销软文、无署名的自媒体转载
  预期形态：区间（而非单点），并标注口径差异
```

**不预先指定证据标准，就会得到一堆"据说"和"大概"。**
:::

## 步骤二：检索与阅读

研究场景的检索和普通 RAG 不同：**要广度，也要深度**。

```python {2-10} title="三种检索策略组合使用"
def research_step(subquestion, state):
    # 1. 广度：多角度查询，避免单一视角
    queries = generate_query_variants(subquestion, n=4)     # 换词、换角度、换语言
    hits = [search(q, top_k=10) for q in queries]

    # 2. 深度：对高价值来源做全文阅读
    for doc in rank(hits)[:5]:
        if doc.relevance > 0.8 and not state.read(doc.id):
            state.evidence += read_and_extract(doc, subquestion)  # 抽取结构化证据

    # 3. 追溯：顺着引用链找一手来源
    for ev in state.evidence:
        if ev.is_secondary and ev.cites:                    # 二手来源 → 找原始出处
            state.queue.append(ev.cites)

    return state
```

:::callout warn 只读摘要会带来系统性偏差
搜索引擎返回的摘要往往是**最吸引点击的段落**，而不是最准确的信息。研究 Agent 必须能**打开原文、定位到具体段落**，否则整个结论建立在你无法核实的二手信息上。

所以 `read_document(doc_id, section)` 这类"深入阅读"工具是必需的，而不是可选的。
:::

## 步骤三：交叉验证

这是研究 Agent 最核心的价值。**单一来源不足以下结论。**

```python {3-12} title="证据冲突处理"
def cross_validate(findings: list[Finding]) -> list[Claim]:
    claims = []
    for topic, items in group_by_topic(findings).items():
        values = [i.value for i in items]
        if agrees(values):                                  # 多方一致
            claims.append(Claim(topic, consensus(values), confidence="high",
                                sources=[i.source for i in items]))
        elif explainable_divergence(items):                 # 分歧可解释（口径不同）
            claims.append(Claim(topic, as_range(values), confidence="medium",
                                note=explain_caliber(items)))   # 明确标注口径差异
        else:                                               # 无法解释的分歧
            claims.append(Claim(topic, most_credible(items), confidence="low",
                                note="来源间存在实质分歧，需人工判断"))
    return claims
```

:::callout key 三种情况的处理方式完全不同
| 情况 | 处理 | 输出形态 |
| --- | --- | --- |
| 多方一致 | 采信 | 单点值 + 多个引用 |
| 分歧可解释（口径/时间/样本不同） | 采信并标注 | **区间** + 口径说明 |
| 无法解释的分歧 | 降级 | 明示分歧，不下结论 |

**最忌讳的做法是把分歧"平均"掉，得出一个两边都不成立的中值。**
:::

## 步骤四：识别信息缺口

收敛阶段要主动问"我缺什么"：

```text {1-7} title="缺口识别"
对每个子问题检查：
- 有量化数据吗？（还是只有定性描述）
- 有一手来源吗？（还是全是转载）
- 有反面证据吗？（是否只找到支持性信息）
- 有时间变化吗？（是否有最新数据）
- 来源多样性够吗？（是否全部来自同一家机构）

任一为"否" → 生成补充检索任务
```

:::callout danger 警惕"单边证据"
如果某个结论的所有支持证据都来自同一个利益相关方（比如都是某家厂商的案例分享），这个结论的可信度必须降级，并明确标注。

**主动寻找反面证据**是研究 Agent 区别于"营销文案生成器"的核心能力。
:::

## 步骤五：成文与引用

```markdown title="输出结构"
## 核心结论
（3~5 条，每条一句，标注置信度）

## 论据
### 1. 市场规模
数据区间 120~180 亿元 [1][3]（口径差异：含/不含 SaaS 收入）
...

## 分歧与不确定性
- 关于增长率，[2] 给出 45%，[4] 给出 22%，差异源于统计口径不同。

## 信息缺口
- 缺少细分赛道的独立数据，现有数据均来自综合报告。

## 参考来源
[1] XXX 研究院《2026 企业 AI 报告》p.23  2026-03
[2] ...
```

:::callout tip 引用的三个要求
1. **可定位**：精确到页码或章节，而不是只给文档名。
2. **可溯源**：给出原始链接或文档 ID。
3. **可核验**：引用编号必须与正文断言一一对应（可自动化校验，见第 14 章）。

**"无法核验的引用"等于没有引用。**
:::

## 成本与时间控制

研究 Agent 是成本最高的场景之一，必须严格控制：

| 控制项 | 建议值 | 说明 |
| --- | --- | --- |
| 最大检索轮次 | 8~12 | 超过说明问题拆得不好 |
| 每个子问题最大来源数 | 10 | 避免信息过载 |
| 单次阅读的 token 上限 | 8K | 超长文档要分段读 |
| 已读文档去重 | 强制 | 重复阅读是很常见的浪费 |
| 总时长上限 | 3~5 分钟 | 超过应返回阶段性成果 |
| 无新证据轮次上限 | 2 | 连续两轮没有新发现就收敛 |

:::callout info 允许"分阶段交付"
研究任务耗时长，不要等全部完成才返回。做法：

1. **先返回研究计划**（用户可确认方向）；
2. 每个子问题完成后**增量返回**（用户可提前看到进展）；
3. 最后返回**完整报告**。

这样即使用户中途打断，也已经拿到有价值的部分。
:::

## 效果指标

| 指标 | 目标 |
| --- | --- |
| 引用可核验率 | ≥ 98% |
| 来源多样性（独立机构数） | ≥ 4 |
| 结论被人工认可率 | ≥ 80% |
| 平均检索轮次 | ≤ 10 |
| 单次任务成本 | 有明确上限并在预算内 |

## 本章要点

- 研究 Agent 的循环是**先发散收集、再收敛成文**；前 N 轮只收集不结论。
- 拆解子问题时要**指定证据标准**（来源等级、数量、预期形态）。
- 检索要"广度（多角度查询）+ 深度（打开原文）+ 追溯（找一手来源）"；**只读摘要会造成系统性偏差**。
- **交叉验证**是核心价值：一致则采信、可解释分歧则给区间、不可解释则降级并明示。
- 主动识别**信息缺口**，寻找**反面证据**。
- 引用必须**可定位、可溯源、可自动化核验**。
- 严格成本控制，并**允许分阶段交付**。
